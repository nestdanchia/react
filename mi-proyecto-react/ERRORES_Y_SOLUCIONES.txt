Has pasado por todos los dolores clásicos: desde el problema de los Closures obsoletos (capturar variables viejas) hasta las Keys duplicadas que rompen el algoritmo de reconciliación.
Sin embargo, me gustaría dejarte una reflexión técnica final sobre tu "Solución Definitiva" (el propsVersion y el setTimeout):
💡 La "Cura" vs. La "Causa"
La solución de usar una key dinámica con propsVersion es lo que llamamos un Hard Reset. Funciona porque obligas a React a tirar a la basura el componente viejo y montar uno nuevo desde cero.
¿Por qué fue necesario en tu caso?
Si React no actualizaba la prop stock a pesar de que el estado cambiaba, generalmente se debe a que en algún punto la cadena de inmutabilidad se rompió o el componente Item estaba ignorando las props entrantes (quizás por haber guardado el stock en un useState interno al inicio).
Riesgos del Hard Reset (key={...-propsVersion}):
Pérdida de estado local: Si el usuario estaba escribiendo en un input dentro del Item o tenía algo seleccionado, al cambiar la key, eso se borra porque el componente "muere" y "nace" otro.
Rendimiento: Recrear el DOM es más costoso que simplemente actualizar un texto.
🚀 El siguiente nivel (Best Practices)
Para que en tu próximo proyecto no necesites el propsVersion, el flujo ideal sería:
Inmutabilidad estricta: setProductos(prev => prev.map(p => p.id === id ? {...p, stock: nuevo} : p)).
Props puras: En el Item, usa {stock} directamente en el JSX, nunca lo pases a un useState local.
Memoización (Opcional): Si quieres optimizar, usa React.memo(Item) para que solo se renderice el producto que realmente cambió.

## 🚨 ERRORES ENCONTRADOS

### 1. ERROR DE PARSING - Función async dentro de useEffect
**Problema:**
```javascript
useEffect(() => {
  const cargarProductos = async () => { ... } // ❌ Función async adentro
  cargarProductos();
}, []);
```

**Error:** "Parsing error: Unexpected token 'async'"

**Solución:**
```javascript
const cargarProductos = async () => { ... } // ✅ Función afuera
useEffect(() => {
  cargarProductos();
}, []);
```

---

### 2. ERROR DE IMPORT/EXPORT - Componente sin export default
**Problema:**
```javascript
export function TiendaVirtual({ mensaje }) { ... } // ❌ Solo export nombrado
// En App.jsx:
import { TiendaVirtual } from './components/ItemListContainer'; // ❌ Buscaba default
```

**Error:** "TiendaVirtual is not exported"

**Solución:**
```javascript
export function TiendaVirtual({ mensaje }) { ... }
export default TiendaVirtual; // ✅ Agregar export default
```

### 4. ERROR DE CLOSURE DESACTUALIZADO - Stock volvía al valor original
**Problema:**
```javascript
const crearCallbackCompra = (productoId) => {
  return (cantidad) => {
    const producto = productos.find(p => p.id === productoId); // ❌ Estado desactualizado
    setProductos(productosActualizados => {
      return productosActualizados.map(p => ...);
    });
  };
};
```

**Error:** El stock disminuía pero luego volvía al valor original

**Causa:** El closure capturaba una referencia desactualizada del estado `productos`

**Solución:**
```javascript
const crearCallbackCompra = (productoId) => {
  return (cantidad) => {
    setProductos(productosActuales => { // ✅ Usar forma funcional
      const producto = productosActuales.find(p => p.id === productoId); // Estado actualizado
      return productosActuales.map(p => ...);
    });
  };
};
```

---

### 5. ERROR DE DOBLE EJECUCIÓN - Callback se ejecutaba dos veces
**Problema:**
Los logs mostraban que el callback de compra se ejecutaba dos veces por cada clic

**Causa:** Posible conflicto con React.StrictMode o event bubbling

**Solución Intentada (no funcionó):**
```javascript
const comprasEnProceso = useRef(new Set());
const compraKey = `${productoId}-${cantidad}`;
if (comprasEnProceso.current.has(compraKey)) return;
comprasEnProceso.current.add(compraKey);
```

### 6. ERROR DE REFS PARALELAS - Estado bloqueado por useRef
**Problema:**
```javascript
const productosRef = useRef([]);
setProductos(productosActualizados => {
  productosRef.current = productosActualizados; // ❌ Estado paralelo
  return productosActualizados;
});
```

**Error:** El estado se actualizaba pero la UI no reflejaba los cambios

**Causa:** React ignoraba las refs para decidir cuándo renderizar

**Solución:**
```javascript
// Eliminar todas las refs y usar solo estado puro de React
setProductos(productosActuales => {
  return productosActuales.map(p => ...); // ✅ Solo estado React
});
```

### 8. ERROR DE KEY DUPLICADAS - React no re-renderizaba componentes
**Problema:**
```javascript
{productos.map(producto => (
  <Item key={producto.id} ... /> // ❌ Keys duplicadas si hay IDs repetidos
))}
```

**Error:** Componentes no se re-renderizaban con nuevas props

**Solución:**
```javascript
{productos.map((producto, index) => (
  <Item key={`${producto.id}-${index}`} ... /> // ✅ Key única
))}
```

---

### 9. ERROR DE INMUTABILIDAD - React no detectaba cambios
**Problema:**
```javascript
// Intento de inmutabilidad incorrecto
const productosActualizados = productosActuales.map(p => ...);
const productosConNuevaReferencia = [...productosActualizados];
```

**Error:** React seguía sin detectar los cambios

**Solución Final:**
```javascript
// Inmutabilidad simple y directa
return productosActuales.map(p => 
  p.id === productoId 
    ? { ...p, stock: p.stock - cantidad } // ✅ Objeto nuevo
    : p
);
```

## 🎯 PROBLEMA FINAL Y SOLUCIÓN DEFINITIVA

### El Problema Real:
El estado se actualizaba CORRECTAMENTE (comprobado con logs), pero los componentes Item no recibían las nuevas props.

### Síntomas:
- ✅ Logs mostraban stock actualizado (5 → 4)
- ✅ Estado global se modificaba correctamente
- ✅ Calculos locales funcionaban ("Quedarían 4 unidades")
- ❌ Etiqueta de stock no se actualizaba en UI
- ❌ useEffect en Item no detectaba cambios

### Causa Raíz:
React no estaba re-renderizando los componentes Item a pesar de que el estado cambiaba.

### Solución Definitiva:
```javascript
// 1. Estado de versión para forzar actualización
const [propsVersion, setPropsVersion] = useState(0);

// 2. Incrementar versión después de actualizar estado
setTimeout(() => {
  setPropsVersion(prev => prev + 1);
}, 50);

// 3. Key dinámica que fuerza recreación completa
{productos.map((producto, index) => (
  <Item 
    key={`${producto.id}-${index}-${propsVersion}`}
    stock={producto.stock}
    ...
  />
))}
```

### ¿Por qué funciona?
1. **Estado se actualiza** → `productos` cambia (5 → 4)
2. **propsVersion incrementa** → `0` → `1`
3. **Key cambia** → `2-0-0` → `2-0-1`
4. **React destruye y recrea** el componente Item
5. **Nuevo componente recibe** las props actualizadas

## 📊 LECCIONES APRENDIDAS

### 1. Estado Puro de React
- ✅ Usar solo `useState` y `useEffect`
- ❌ Evitar `useRef` para estado paralelo
- ❌ No usar `useReducer` para forzar updates

### 2. Inmutabilidad Correcta
- ✅ `.map()` siempre crea array nuevo
- ✅ `{...obj}` siempre crea objeto nuevo
- ❌ Nunca modificar el estado original

### 3. Keys de React
- ✅ Keys deben ser únicas y estables
- ✅ Usar `${id}-${index}` para garantizar unicidad
- ❌ Nunca usar solo `id` si puede haber duplicados

### 4. Closures y Estado
- ✅ Usar forma funcional de `setState`
- ❌ No capturar estado en closures
- ✅ Dejar que React maneje el ciclo de vida

### 5. Debugging
- ✅ Logs exhaustivos para identificar problemas
- ✅ Verificar estado antes/después de cambios
- ✅ Comprobar si los componentes se re-renderizan

### 💡 La "Cura" vs. La "Causa"

1. **Inmutabilidad estricta:** `setProductos(prev => prev.map(p => p.id === id ? {...p, stock: nuevo} : p))`

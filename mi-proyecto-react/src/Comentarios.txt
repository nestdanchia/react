useState: El "motor" de la pantalla. Si cambia, el usuario ve el cambio.
useRef: La "caja fuerte" silenciosa. Guardás datos en una dirección de memoria fija (puntero) para usarlos después, sin molestar a la interfaz.
useEffect: El "director de escena". 
Decide cuándo deben ocurrir las cosas 
(al entrar, al cambiar algo o al irse).
useRef(null) 👉 Fabrica el objeto { current: null }.
const timerRef 👉 Guarda ese objeto para que no se pierda.
timerRef.current 👉 Es el único lugar donde podés escribir o leer tus datos
import { useState, useEffect, useRef } from "react";

export default function Contador() {
  const [segundos, setSegundos] = useState(0);
  const timerRef = useRef(null); // Puntero estable al ID del proceso

  useEffect(() => {
    // 1. LÓGICA: Solo inicia el proceso si el estado es menor a 10
    if (segundos < 10) {
      timerRef.current = setInterval(() => {
        setSegundos(s => s + 1); // Actualiza el estado
      }, 1000);
    }

    // 2. LIMPIEZA: Se ejecuta antes de cada nuevo render o al desmontar
    return () => {
      clearInterval(timerRef.current);
      console.log("Limpieza de memoria ejecutada");
    };
  }, [segundos]); // 3. DEPENDENCIA: Re-ejecuta el efecto cuando 'segundos' cambia

  return (
    <div style={{ textAlign: 'center', marginTop: '50px' }}>
      <h1>{segundos < 10 ? `Contando: ${segundos}` : "¡Tiempo cumplido!"}</h1>
      <h2>{segundos} segundos</h2>
      
      {/* Botón para resetear el puntero y el estado */}
      {segundos === 10 && (
        <button onClick={() => setSegundos(0)}>Reiniciar</button>
      )}
    </div>
  );
}
Análisis técnico del flujo en JS
El objeto timerRef
Al ejecutar useRef(null), React crea el objeto { current: null }. 
Este objeto no cambia de dirección de memoria en toda la vida del
 componente.
Cuando hacemos timerRef.current = setInterval(...), estamos guardando 
el ID numérico del proceso dentro de esa dirección de memoria.
La ejecución del useEffect
Evaluación: React entra al efecto porque detectó que 
segundos cambió (o es el primer render).
Condición: Verifica if (segundos < 10).
Suscripción: Si es true, le pide al navegador (Web API) 
que cree un intervalo. El navegador devuelve un ID y lo
 guardamos en nuestro puntero.
Finalización: Cuando segundos llega a 10, la condición del if es false.
 El efecto se ejecuta pero no crea un nuevo intervalo. 
 El ciclo se rompe.
El rol del return (Cleanup)
Es la instrucción de recolección de basura. Sin esta línea, cada segundo estarías creando un proceso nuevo sin matar el anterior, lo que saturaría la cola de tareas del navegador (Task Queue) y el procesador.

useState maneja el número.
useEffect maneja el tiempo.
&& maneja qué ve el usuario.

import { useState, useEffect, useRef } from "react";

export default function TiendaPro() {
  // 1. ESTADO: El stock actual y el producto que se está comprando
  const [stock, setStock] = useState(10);
  const [comprando, setComprando] = useState(false);
  
  // 2. REFERENCIA: Puntero al diálogo nativo
  const dialogRef = useRef(null);

  // 3. EFECTO: Si 'comprando' pasa a true, resta 1 al stock y cierra el modal
  useEffect(() => {
    if (comprando) {
      // Simulamos un pequeño delay de procesamiento
      const timer = setTimeout(() => {
        setStock(prev => prev - 1); // Resta 1 unidad
        setComprando(false);        // Finaliza el proceso
        dialogRef.current.close();  // Cierra el modal vía Referencia
      }, 1000);

      return () => clearTimeout(timer); // Limpieza de memoria
    }
  }, [comprando]);

  return (
    <div style={{ padding: '20px', fontFamily: 'sans-serif' }}>
      <h1>Laptop HP Gamer</h1>
      <p>Stock disponible: <strong>{stock}</strong></p>

      {/* RENDERIZADO CONDICIONAL: Solo muestra el botón si hay stock */}
      {stock > 0 ? (
        <button onClick={() => dialogRef.current.showModal()}>
          Comprar ahora
        </button>
      ) : (
        <p style={{ color: 'red' }}>⚠️ Producto agotado</p>
      )}

      {/* MODAL NATIVO */}
      <dialog ref={dialogRef} style={{ borderRadius: '10px', border: '1px solid #ccc', padding: '20px' }}>
        <h3>¿Confirmar compra?</h3>
        <p>Se descontará 1 unidad del inventario.</p>
        
        {/* Si está procesando, mostramos un mensaje, sino los botones */}
        {comprando ? (
          <p>Procesando pago...</p>
        ) : (
          <div>
            <button onClick={() => setComprando(true)}>Sí, confirmar</button>
            <button onClick={() => dialogRef.current.close()}>Cancelar</button>
          </div>
        )}
      </dialog>
    </div>
  );
}
Análisis Técnico de la Arquitectura
1. Gestión de Memoria (useRef)
Usamos dialogRef para guardar el puntero al elemento <dialog>.
Esto nos permite ejecutar .showModal() y .close() sin disparar renderizados innecesarios de React.
2. Sincronización de Procesos (useEffect)
El efecto tiene como dependencia [comprando].
Cuando el usuario hace clic en "Confirmar", el estado cambia y el efecto se dispara.
Dentro del efecto, usamos un proceso asíncrono (setTimeout) para emular una petición al servidor.
Al terminar, mutamos el estado de stock y volvemos comprando a false.
🚀 ¿Qué aprendimos con este sistema?
Interacción directa: Cómo el useEffect puede controlar un elemento del DOM guardado en un useRef.
Flujo de datos: Cómo un cambio de estado (comprando) dispara una lógica de negocio que termina afectando a otro estado (stock).

## 🏃‍♂️ LA "CARRERA DE RELEVOS" DEL USEEFFECT

Para entender cuándo ocurre la **primera limpieza**, imagina una carrera:

1. **Salida (0 seg):** El Efecto 1 arranca y guarda el `ID: 101` en la caja fuerte (`timerRef.current`).
2. **Relevo (1 seg):** El estado cambia. **ANTES** de que el Efecto 2 empiece a correr, React activa la limpieza del Efecto 1.
3. **La Limpieza:** Mira la caja fuerte, ve el `ID: 101` y lo borra (`clearInterval`). ¡La pista queda limpia!
4. **Nueva Vuelta:** El Efecto 2 arranca, crea el `ID: 102` y lo guarda.

### Conceptos Clave:
- **La Limpieza no es el final, es el puente:** No ocurre "al final" de la vida del componente, sino justo antes de que el siguiente efecto tome el control.
- **useRef es el testigo:** Es el objeto que se pasan los efectos entre sí para saber qué es lo que tienen que limpiar del pasado.

**En resumen:** Sí, en la "primera limpieza" (que ocurre cuando pasas de 0 a 1 segundo), se borra el ID que se creó al inicio. Sin esa limpieza, tendrías un "fantasma" del primer segundo corriendo en paralelo con el segundo actual.

Usamos setStock(prev => prev - 1).
Técnicamente: Esto es más seguro que hacer setStock(stock - 1), porque garantiza que estamos restando sobre el valor real más reciente en la memoria, evitando errores si el usuario hiciera muchos clics rápidos.

## �️ CONTRIBUCIÓN TÉCNICA: GESTIÓN DE STOCK PRO

### 1. La Integridad del Dato (Atomicidad)
Cuando usas `setStock(prev => prev - 1)`, estás aplicando **programación funcional**. 
- **Por qué importa:** En aplicaciones de alto tráfico (como un CyberMonday), si dos procesos intentan restar stock al mismo tiempo, usar el valor previo (`prev`) asegura que no se pierda ninguna resta. Es como un cajero contando billetes: siempre se basa en lo que tiene en la mano en ese instante exacto.

### 2. El "Cortocircuito" de UI
Un concepto clave en stock es deshabilitar la acción **antes** de que el error ocurra.
- **Estrategia:** El botón de compra debería tener la propiedad `disabled={stock === 0}`.
- **Efecto:** Esto mejora la UX (Experiencia de Usuario) porque no permites que el usuario se ilusione con una compra que no puede completar.

### 3. Sincronización vs Estado Local
- **Estado Local:** El `stock` que manejas con `useState` es perfecto para la respuesta inmediata en pantalla.
- **Sincronización:** El `useEffect` es tu puente. Si el stock llega a 0, podrías disparar un efecto que avise al sistema de "Reposición" o que cambie automáticamente la etiqueta a "Agotado".

¿Te gustaría que implementemos una lógica de **"Reserva Temporal"**? Donde el stock baje apenas abren el modal, pero si cancelan la compra (cierran el modal), el stock se devuelva automáticamente al estado original. ¡Eso llevaría tu contador al siguiente nivel!

## 💡 RESUMEN EDUCATIVO: FLEXBOX vs GRID

En este proyecto hemos combinado ambas herramientas para lograr un diseño profesional. Aquí tienes la explicación de qué significan y cuándo usarlas:

### 1. CSS GRID (El orquestador de la Galaxia)
Lo usamos en **ItemList.module.css** para crear la cuadrícula de productos.
- **Concepto:** Trabaja en **2 dimensiones** (filas y columnas al mismo tiempo). 
Es ideal para el diseño general de la página o galerías.
- **Comandos clave usados:**
    - `display: grid`: Define que el contenedor se comporte como una rejilla.
    - `grid-template-columns: repeat(4, 1fr)`: Divide el espacio en 4 columnas iguales.
     El `fr` es una "fracción" del espacio disponible.
    - `gap: 16px`: Establece el espacio entre las celdas sin usar márgenes manuales.

### 2. FLEXBOX (El experto en alineación lineal)
Lo usamos en **Header.module.css** y **Navbar.css** para alinear el logo y los enlaces.
- **Concepto:** Trabaja en **1 dimensión** (una fila o una columna). Es perfecto para alinear elementos dentro de un contenedor, como menús o botones.
- **Comandos clave usados:**
    - `display: flex`: Convierte el contenedor en un eje flexible.
    - `justify-content: space-between`: Empuja los elementos a los extremos 
    (ej: Título a la izquierda, Nav a la derecha).
    - `align-items: center`: Centra los elementos verticalmente para 
    que queden perfectos respecto al fondo.
    - `gap: 15px`: Espaciado consistente entre los botones del menú.

### ¿Cuándo usar cuál?
- **Usa Grid** cuando quieras definir una estructura rígida de filas y columnas 
(como tu catálogo de laptops).
- **Usa Flex** cuando quieras distribuir elementos en una línea y 
necesites control total sobre su alineación y espaciado (como tu barra de navegación).

## 🛠️ LECCIÓN: FILTRADO DE DATOS EN JSX

### Encadenamiento de Métodos: .filter().map()
Es la mejor práctica para mostrar listas condicionales. 
- **Paso 1 (.filter):** Crea una nueva lista con solo los elementos que cumplen la condición (ej: `stock > 0`).
- **Paso 2 (.map):** Recorre esa lista filtrada para crear los elementos visuales.

**¿Por qué en ItemList y no en Item?**
1. **Limpieza del DOM:** Si filtras en `ItemList`, los productos sin stock ni siquiera se crean. Si usas un `if` dentro de `Item` que devuelva `null`, React crea una "celda vacía" en tu Grid, dejando huecos feos en el catálogo.
2. **Responsabilidad:** `ItemList` decide **qué** se muestra. `Item` decide **cómo** se muestra un producto individual.
